# Plan 0001. Build 6W v0.1

Goal: turn the blueprint into a working skill that runs on at least one tested host, scores deterministically, saves and resumes state, and exports one offline HTML blueprint plus a consistent Markdown handoff from the same state. The conversational skill already exists. This plan adds the schema, the scripts, the templates, the examples, the tests and the host records.

## Context

- Specification: `../../BLUEPRINT.md`. Sections 6 (scoring), 8 and 9 (outputs), 11 (system design) and 12 (layout) are the contracts this plan implements.
- Skill: `../../skills/6w/SKILL.md`. It must keep working at every phase. It stays under 500 lines and names only files that exist.
- Rubric: `../../skills/6w/references/scoring-rubric.md`.
- Runtime decision: Node.js 18 or later, plain `.mjs`, no runtime dependencies. Tests use `node --test`.
- Gate: `npm test` runs `scripts/check-repo.mjs`. Every phase adds its checks to that gate or to `node --test`.
- Constraint: project state lives in the user's project under `.6w/`, never in this repository.

## Phase 1. Contract

Done when a complete example and a partial example are represented in state without invented data, validate against the schema, and produce the expected scores.

- [x] Write `skills/6w/schemas/state.schema.json` with the records in blueprint section 11.3, stable ID patterns, decision status and evidence status enums, and `schemaVersion` and `rubricVersion` fields.
- [x] Write `skills/6w/schemas/export-manifest.schema.json` with version, state hash, generated files and validation results.
- [x] Write `skills/6w/scripts/validate.mjs`: schema check without a dependency (hand-written validator over the schema's subset), ID resolution across links. Exit code non-zero with actionable diagnostics. The freshness check moves to phase 2 with `state.mjs`.
- [x] Write `skills/6w/scripts/score.mjs`: reads state, computes each W score with the formula and caps from the rubric, writes ratings and rationale back, prints the scoreboard.
- [x] Add `skills/6w/scripts/*.test.mjs` for the formula, rounding half up, each cap condition and its clearing, and ID resolution failures.
- [x] Write `examples/menulens-complete/state.json` (a finished foundation) and `examples/menulens-partial/state.json` (the naive baseline with every cap active) with every claim labeled. A third example with user-locked Ws is still to do.
- [x] Add `node --test skills/6w/scripts` to `package.json` test script.

## Phase 3. Output

Depends on phase 1. Done when one validated state produces a complete offline bundle.

- [x] Write the HTML template (as `skills/6w/templates/blueprint.css` plus the markup in `render.mjs`) with inline CSS, the sections, sticky navigation, collapsible blocks that search can reveal, print stylesheet, and no external reference. Marketing and technical sections render what the state holds and say what is missing.
- [x] Write the ten Markdown files as code in `skills/6w/scripts/handoff.mjs` rather than as templates; a template language would have been larger than the generator.
- [x] Write `skills/6w/scripts/render.mjs` for HTML: validates first, escapes every imported string, links only http(s) locators, deterministic for a fixed timestamp, atomic write. Markdown rendering and SVG sanitizing are still to do.
- [x] Write `skills/6w/scripts/export.mjs`: render into a temporary directory, validate, compute the content hash excluding timestamps, finalize atomically, keep the previous bundle on failure.
- [x] Write the fallback in `skills/6w/scripts/diagrams.mjs`: inline SVG for workflow, architecture and sequence plus a text description. ERD reports that no entities are recorded instead of drawing.
- [x] Add tests: escaping of script-like text, URL scheme filter, hash stability, JavaScript-disabled readability (every section in the DOM without scripts), no external reference, determinism, the committed demo matching the current export, and a failed export leaving the previous bundle intact.
- [x] Render the complete example to `docs/demo/menulens/index.html`, served by GitHub Pages at https://pongsiritk.github.io/6w/demo/menulens/. The partial example is rendered in tests only.

## Phase 5. Evaluation

Depends on phase 4. Done when every acceptance criterion in blueprint section 17 has a deterministic test or a recorded manual check.

- [ ] Run browser checks: offline open, JavaScript disabled, keyboard navigation, print, mobile width.
- [ ] Run three pilot sessions on real ideas. Record question count, time to first canvas, and clarification requests.

- [ ] Update `AGENTS.md` and `CLAUDE.md` file maps for the new directories.

## Validation

- Phase 1: `npm test` passes. `node skills/6w/scripts/score.mjs examples/complete/state.json` prints the expected scoreboard. `validate.mjs` rejects a fixture with a missing linked ID.
- Phase 2: a transcript fixture for each user control reaches the expected state.
- Phase 3: `export.mjs` on both examples produces `6w-blueprint.html` and `.6w/handoff/` with a matching state hash. Open the HTML with the network disabled.
- Phase 4: `docs/compatibility.md` has at least one row with result full.
- Phase 5: every row of blueprint section 17 points at a passing test or a dated manual record.
- Phase 6: a clean machine follows the README and reaches an exported bundle.

## Out of scope

- A hosted service, accounts or collaboration.
- In-browser editing of the blueprint.
- Industry-specific rubrics.
- Issue-tracker export.
- Automatic installation of archify or any third-party code.
